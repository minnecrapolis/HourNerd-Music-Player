PANDORA CONNECTION SETUP (REQUIRED)
Public builds do not contain Pandora partner connection settings. Obtain one
separately from your integration provider or administrator. It is not your
personal Pandora password. After installation, open Pandora connection setup
on the sign-in page, enter all three supplied values and save them. Windows encrypts it
for your current Windows account on this computer. Then sign in normally with
your personal Pandora email and password. Without a partner connection value,
the installed application cannot sign in or play music.

HOURNERD MUSIC PLAYER 1.1.3 - WINDOWS SETUP EXE BUILDER

1. Close the previous player, including its tray icon, and extract this project
   into a new folder.
2. Install Inno Setup 6 once (only YOU need this, not recipients):

   winget install --id JRSoftware.InnoSetup -e -s winget -i

   Or download from https://jrsoftware.org/isdl.php
3. From this project folder, run:

   powershell -NoProfile -ExecutionPolicy Bypass -File .\Build-Windows-Installer.ps1

   Or double-click Build-Windows-Installer.cmd.

This builds the public application on Windows using Visual Studio 2022,
runs the regression tests, validates the clean public payload, and compiles:

   dist\HourNerd-Music-Player-1.1.3-Setup.exe

Give people that ONE Setup.exe. The build also produces a SHA-256 checksum
and keeps the portable Windows ZIP as an alternative.

NEW USERS
Recipients run Setup.exe and use the installation wizard. It installs for their
Windows account, registers Installed Apps / Programs and Features, creates Start
menu and optional desktop shortcuts, and offers to launch the player.
They sign in with their own Pandora account. They do not need your project,
PowerShell scripts, Visual Studio or Inno Setup. The .NET Framework 4.8.1
runtime is required; Setup checks for it and explains what to install if absent.

WORKING FOLDER
The app and all generated shortcuts use a dedicated, writable per-user folder:
%LOCALAPPDATA%\HourNerd Music Player\Working\Public
It has no dependency on your development folder or current directory.
This launch change is a candidate fix for the installed-copy freeze. It still
requires the Windows focus-switching test below before public release.

UPDATES AND UNINSTALL
Later Setup.exe releases reuse the same product identity and installation
folder. Setup removes the old script install's Programs entry only if it points
to this same installation folder. Uninstall removes installed files and shortcuts,
while preserving per-user accounts and settings. A public install uses a separate
Public profile; an existing development login is intentionally not imported.

BEFORE SHARING
Run Setup.exe on Windows. Test sign-in, several station changes, Settings,
About, loss/return of window focus, tray Exit, reopening from Start, installing
the same version again, and uninstall. Repeat on a clean Windows account without
the source project. This source package has been checked structurally here;
Windows compilation and live installation must be performed on Windows.
The compiler produces an unsigned installer unless you configure code signing.

PRIVATE DATA
The publisher copies an explicit runtime list and curated source, not your
AppData or a general copy of the working folder. It omits settings, caches,
history, logs, debug symbols, private release keys and local build paths.
Public developer credits and the requested Zelle tipping email are retained.
Do not redistribute a ZIP you created by copying your AppData folder.

STARTUP BRANDING (1.1.3)
A HourNerd logo window covers audio initialization. It stays above startup
windows belonging to this process while this app is in the foreground, and
moves behind other apps when the user switches away. It closes after audio
initialization (minimum six-second branding interval), or after fifteen seconds
if initialization does not complete. Escape can dismiss it when focused.
BASS / BASS.NET credits remain in About and bundled license notices.
Third-party binaries and registration checks are unchanged.
Rebuild the installer without -UseExistingDistribution for this code change.

NATIVE WINDOWS INSTALLER (.MSI)
Recipients double-click the .msi and use the native Windows Installer wizard.
No PowerShell, scripts, source project or developer tools run on the recipient
computer. The MSI contains the complete application and supporting files.
The Microsoft .NET Framework 4.8.1 runtime must already be present.

BUILD COMPUTER ONLY
From the project root, build the MSI from your already compiled public ZIP:

  powershell -NoProfile -ExecutionPolicy Bypass -File .\Build-Windows-MSI.ps1

To rebuild both EXE and MSI from the existing public ZIP:

  powershell -NoProfile -ExecutionPolicy Bypass -File .\Build-Windows-Installers.ps1 -UseExistingDistribution

Outputs:
  dist\HourNerd-Music-Player-1.1.3-Setup.msi
  dist\HourNerd-Music-Player-1.1.3-Setup.exe

For a completely fresh application and both installers, omit
-UseExistingDistribution. Inno Setup is needed only for building the EXE;
the MSI builder uses Windows Installer and MakeCab, already provided by Windows.
The MSI build validates the public payload hashes, creates the native package,
then uses Windows Installer to extract a temporary administrative image and
checks every extracted file before publishing the MSI. This does not install
or uninstall the app on the build computer. MSI-build-validation.log contains
build diagnostics and should not be distributed as part of the installer.

INSTALL/UPGRADE
Choose one format. The MSI blocks installation over the EXE/script format,
and the EXE blocks installation over the MSI format. To change formats,
uninstall the existing app first; per-user accounts and settings are preserved.
MSI releases retain a stable UpgradeCode. Per-file component identities are
stable by relative path. The MSI can upgrade earlier MSI releases, blocks
downgrades, and registers its own uninstall entry. Both formats install for
the current Windows user and retain the same public user profile location.
Uninstall does not delete the user profile.
